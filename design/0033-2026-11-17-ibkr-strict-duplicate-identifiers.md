# 重复内容校验的 ID 空白处理补充

## 背景与目标

[0032](0032-2026-11-17-ibkr-duplicate-content-consistency.md) 的独立复核发现：比较文本时去首尾空白，但查重和保存仍使用原始 ID，会使 `ID` 与 ` ID ` 绕过去重。这会破坏用户要求的同 ID 一致性校验。

## 范围与设计取舍

订单 orderID、成交 tradeID 及其父 orderID 必须存在且不含首尾空白；直接拒绝异常 ID，不修剪后改写源标识。正式入库的 orderID 使用同一规则。其他来源文本仍按 0032 的比较规则处理，不修改已有记录、唯一索引或表结构。

本补充仅解决身份键歧义，沿用 0032 的内容比较、UNRECOGNIZED 分类及整批失败清理；不新增订单状态查询或历史重算。

## 实施与验收

1. 在改动前记录本补充并追加索引，再扩展 ID 校验。
2. 用合成数据验证同批和跨批的订单 ID、成交 ID、父订单 ID 空白情况均在查询／保存前拒绝，旧数据不变，正常 ID 继续按 0032 跳过或报冲突。
3. 重跑受影响的新增用例与相关券商回归，记录命令、结果及运行限制；独立复核修复差异。

## 调用方、历史数据和失败处理

异常 ID 从可能被当作新记录变为明确拒绝；ID 正常时业务行为不变。失败沿用原批次清理，只删除本批新增内容；本次不修改、清理或规范化已有历史 ID。

## 当前知识更新

在 IBKR 知识、恢复说明及 TODO 归档中说明身份键的严格空白规则和补充测试；0032 正文保留原样，按本补充解释 ID 处理边界。
