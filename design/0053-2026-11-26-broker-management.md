# 券商管理表格、详情与技术代码

## 背景与范围

券商名称和国家／地区占用了较多列宽，简介在列表中容易被截断。新增和编辑表单只有两个代码选项，无法维护其余四家券商的技术标识。此次调整同一管理页的列表、详情和编辑表单。沿用 [0047 的券商资料范围](0047-2026-11-21-broker-accounts-and-sync-connections.md#数据模型与页面)、[0049 的表格内滚动方式](0049-2026-11-23-responsive-trade-records.md#交易表格)及 [0011 的技术标识与适配器注册机制](0011-2026-04-17-broker-registration.md)。

## 券商表格与详情

为名称、代码、国家／地区和操作设置列宽，剩余空间用于简介的单行预览。超长名称可悬停读取，窄窗口在表格内部横向滚动。操作列提供「详情」和「更新」。只读详情复用列表响应，展示完整名称、代码、国家／地区和简介，并保留简介换行。表格沿用国家／地区筛选和既有编辑入口。

## 券商代码与同步能力

用户确认六个表单选项为 `futu`（富途）、`tiger`（老虎）、`ibkr`（盈透）、`schwab`（嘉信）、`firstrade`（第一证券）和 `csc`（中信建投）。更新表单提示与 `Broker.brokerCode` 注释，说明技术代码也能标识尚未接入同步的券商。代码允许留空，后端沿用现有格式和非空唯一校验，合法代码仍可通过 API 保存。同步发现依赖已注册并有券商资料的适配器，目前为 IBKR 和 Tiger。账户、凭证、批次与交易处理沿用已有规则。

先前单独授权的本地资料维护以 `vortex` 中四家券商的空代码为范围。执行时核对目标实例，在事务中锁定四条资料，仅在名称相符、旧代码为空且新代码未被占用时补齐；任一校验失败即回滚。以新连接和查询接口复核六家代码与字段变更范围。触发器会更新这四条的 `updated_at`，撤回时仅在名称与写入的代码仍匹配时清空。此资料操作独立于功能发布和自动测试。

## 实施与验收

1. 调整现有表格、详情弹窗与代码表单。用合成页面验证 1280 CSS 像素视口下操作列直接可见，窄视口下滚动限于表格。覆盖长简介、空字段、详情关闭后打开编辑、国家／地区筛选、六个选项、新增及编辑提交、回显和清空。
2. 保留后端参数化用例，验证四个新代码可创建、更新，重复时拒绝保存。核对同步发现及拒绝未注册适配器的路径。运行前后端全量单测、前端构建及仓库现有数据库回归；数据库回归使用隔离的临时 PostgreSQL 集群。
3. 同步 [知识索引](../knowledge/README.md)、[前端架构](../knowledge/frontend-architecture.md)和 [账户指南](../docs/accounts.md)，检查差异与文档链接。
