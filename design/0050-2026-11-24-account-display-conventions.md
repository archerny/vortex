# 账户信息展示规范

## 背景与范围

各页面的账户列顺序原先不一致，IBKR 原始数据也缺少发起同步的账户信息。本方案统一表格的账户列顺序、补齐原始数据的同步账户，并区分侧栏中的券商和托管账户入口。沿用 [0047 的账户模型和批次快照](0047-2026-11-21-broker-accounts-and-sync-connections.md)、[0049 的交易表格布局](0049-2026-11-23-responsive-trade-records.md)和 [0015 的原始数据只读入口](0015-2026-04-21-sync-staged-data-viewer.md)。

## 表格列顺序

- 显示托管账户的表格前两列依次为「账户名称」「账户 ID」。适用于交易列表、详情中的相关交易、持仓快照、出入金记录、托管账户、同步批次、同步配置和两张 IBKR 原始数据表。账户 ID 使用券商侧真实标识，规则写入 [研发约定](../AGENTS.md#实现约定)。
- 交易列表与相关交易共用列定义。历史空 ID 显示「待补全」，长账户名称与代码可通过悬停读取，精确费用可换行。缩小横向内边距并保留中等行距，侧栏展开时以 1280 CSS 像素可见末列为目标。
- 同步批次首列读取关联账户当前名称，第二列优先读取批次账户 ID 快照。旧批次沿用当前关联账户 ID 及历史缺失提示。

## IBKR 原始数据

- Orders 和 Confirms 通过暂存行的 `batchId` 匹配 IBKR 批次，首列为「同步账户名称」，取关联账户当前名称，第二列为「同步账户 ID」，取批次快照。账户改名后显示新名称，历史字段缺失显示 `-`。报表的 `accountId` 与 `acctAlias` 以 `IBKR Account ID` 和 `IBKR Acct Alias` 原样展示。
- 两表共用前导列，宽窗口固定账户名称、ID、日期及证券，窄窗口随表格滚动。前端复用暂存查询和批次查询。批次查询失败时仍显示暂存行，并提示无法加载同步账户信息。暂存、导入和清理继续使用现有接口与数据结构。

## 账户菜单

「券商管理」使用机构线框图标，「托管账户」使用同一套 Ant Design 图标中的账户卡片。两个入口沿用现有路由。

## 实施与验收

统一列定义，补充前端批次匹配，调整侧栏图标，同步 [前端架构](../knowledge/frontend-architecture.md)、[前端开发指南](../docs/frontend-guide.md)及 [IBKR 同步知识](../knowledge/broker-sync/brokers/ibkr.md)。使用合成数据点验九张表的列序、历史缺失值、批次筛选、1280 像素交易表末列及两个菜单的跳转。定向测试覆盖不同批次的匹配、快照优先、报表字段保留、查询失败后的降级、费用精度及菜单映射。
