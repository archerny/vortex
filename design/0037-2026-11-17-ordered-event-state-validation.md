# 顺序事件的状态与隔离级别补充

## 背景、范围与取舍

延续 [0035](0035-2026-11-17-ordered-market-events-and-history-locks.md) 的业务规则和 [0036](0036-2026-11-17-market-event-write-coordination.md) 的短事务互斥。实施预审发现：独立处理入口可能收到旧事件对象；旧数据可能出现“未处理但已有派生行”；等待互斥后使用旧事务快照也会破坏边界检查。

## 预期行为与实现

- 单次处理在持锁后按事件类型和 ID 重新读取实际记录；不存在或已撤销时拒绝，已处理时幂等返回，不信任调用方的状态和计算字段。
- 未处理事件若已有派生行，修改、再次处理或撤销均拒绝，要求核对存量异常，不自动修复或删除。
- 写互斥仅支持 PostgreSQL READ COMMITTED，取得互斥前核对当前事务实际隔离级别；其他级别明确失败，避免等待后沿用旧快照。现有默认配置无需改变。
- 既有已处理事件只用日期和证券关联推导历史边界，不重新校验与锁定无关的旧计算参数。新处理仍完整校验输入。

## 验证、影响与文档

补充旧对象、已撤销对象、异常派生行和不同隔离级别回归；临时数据库验证真实事务及等待后重新检查。没有表结构变更，不重写历史数据。冲突由原事务回滚，普通调用方收到明确错误。更新市场事件及运行说明，保留先前方案原文。
