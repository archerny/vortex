# 默认信任 IBKR 报表中的订单与成交已执行完成

## 背景与目标

在讨论同订单后续成交、报表查询窗口和 `Code=P` 后，用户于 2026-11-17 决定：默认相信 IBKR 同步报表中的记录均为已执行完成的订单和交易。以此简化当前项目的导入范围，不开发订单执行过程的跟踪与合并。

这是项目采用的业务前提，不是经运行验证的券商终态保证。本次仅记录决定、同步当前知识并调整待办边界，不实现同 ID 内容变化的处理。

## 范围与历史方案

沿用 [0013 IBKR 暂存与订单映射](0013-2026-04-21-ibkr-staging-schema.md) 的订单汇总入账和成交明细暂存，沿用 [0018 导入一致性](0018-2026-04-22-broker-import-consistency-v2.md) 的批次失败清理。历史方案正文保留原样。

## 设计与关键取舍

- 默认将 Trade Confirmation Flex 返回的 `Order` 和 `TradeConfirm` 当作已执行完成的订单及成交记录，按报表内容处理，不额外证明订单终态。
- 不为本项接入 TWS／Web API 查询原始委托数量、剩余数量或最终状态，不维护挂单和部分成交的生命周期，不自动拼接或持续更新未完成订单。
- 不因为成交明细带有 `Code=P` 或同订单包含多笔成交就拒绝导入；这些信息不用于推翻上述业务前提。
- 该决定不取消现有结构、日期、数量、金额精度和来源映射规则，也不把查询窗口完整性或重复数据的一致性视为已验证。
- 同一业务 ID 的新增成交或内容差异仍属于需要处理的数据一致性问题。默认信任已完成，不等于允许同 ID 的不同内容被静默跳过；不因本决定关闭对应 P1 待办。
