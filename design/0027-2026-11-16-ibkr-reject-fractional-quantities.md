# IBKR 导入明确拒绝非整数数量

## 背景与目标

[IBKR 审阅 R5](../docs/audits/2026-11-16-ibkr-sync-review.md#r5--p1数量转换会静默截断小数并允许整数溢出) 确认导入 Worker 使用 `BigDecimal.intValue()`，会将 1.5 截为 1，也可能把超范围整数溢出为小整数。用户于 2026-11-16 明确决定：当前不支持小数股，不截断或四舍五入，遇到非整数数量明确拒绝导入；以后实际遇到业务样例再决定是否升级数量模型。

本方案沿用 [0013 暂存设计](0013-2026-04-21-ibkr-staging-schema.md) 的原始文本暂存和订单粒度正式交易，修正其中的数量转换规则；沿用 [0018 整批失败清理](0018-2026-04-22-broker-import-consistency-v2.md) 与 [0019 独立失败记录事务](0019-2026-04-23-broker-import-data-loss-fix.md)，不修改历史方案正文。

## 范围与预期行为

- 只修改 IBKR 暂存订单到正式交易的数量校验，以及失败批次的原因展示。其他券商、手工录入、持仓和市场事件算法不在本次范围内。
- 原始数量仍按文本解析与暂存。正式导入使用的订单数量必须是数值上严格的非零整数，绝对值不超过 2147483647。卖出负数继续取绝对值，方向仍由 BUY/SELL 表达。
- 100、100.0、-100.000 均可无损转换；1.5、-1.5、极小非零小数均失败。零、缺失、非法数字和超出整数范围的数量也明确失败。不得先转为整数再检查。
- 以订单汇总为正式导入粒度：成交确认继续作为原始明细暂存，不对其数量取整，不新增逐成交正式交易。订单汇总数量为整数时，不因其文本带小数点而拒绝。
- 已有外部订单仍沿用既有去重，不更新既有正式交易；本次不修复同订单更新问题，也不对历史账本做修正或重算。

## 设计与关键取舍

1. 在 `IbkrImportWorker` 中先用 BigDecimal 解析原始数量并取绝对值，校验非零、无非零小数位，再使用 `intValueExact()` 检查整数范围。错误分类为 UNRECOGNIZED，使用固定原因说明，不在新增错误中拼接原始数量或解析异常内容。
2. 保留 `ImportOneFailedException` → ImportService 调用独立 `markFailed` → Adapter 统计失败 → 执行器统一清理的链路。混合批次内即使其他订单已写入，也清理本批所有正式和暂存记录；其他批次不受清理影响。重复提交同一不支持的数据仍失败。
3. 为保证清理后仍能看到拒绝原因，订单仓储增加按批次和 FAILED 状态读取首条记录的有界查询。Adapter 将其已有错误说明附加到批次失败摘要；没有可用说明时保留现有计数摘要。消息格式增加说明文字，API 字段和状态机不变。
4. 数量实体和数据库列继续为整数，没有 schema、依赖或配置变更。将来支持小数股需要另写方案，统一考虑数据库、接口、持仓和历史数据，不能只放宽导入校验。

## 实现步骤

1. 写入本方案和索引，按用户决定调整数量 TODO 的验收口径。
2. 修改数量转换；补充 Worker 回归测试，覆盖小数、整数文本、正负数量、零、非法值和整数边界，并验证拒绝发生在正式记录保存前。
3. 增加首条失败查询和批次摘要说明；补充缺少说明时的回退测试。
4. 使用真实 Parser、Staging/Import Service 与 Worker、Adapter、执行器和清理策略，配合 Mockito 内存仓储／网络，验证混合批次拒绝、清理、保留其他批次和再次提交行为，不连接数据库或 IBKR。
5. 在既有 Ubuntu 环境运行相关单测，完成独立复核；同步当前知识和故障处理说明，达到验收后将 TODO 移入归档。

## 验证与验收

- Ubuntu `ubuntu-dev`，当前工作树，既有 Java/Maven，优先离线依赖缓存；输出在 `backend/target/`，JVM 临时目录 `/tmp`。
- 纯内存单测覆盖 1.5、-1.5、0.25、极接近整数的小数，确认失败且不保存正式交易；接受合法的正负整数及 100.000，确认数量、价格和金额未被改写。
- 覆盖 null、空白、非法数字、零、Integer.MAX_VALUE、正负超范围及此前溢出为 1 的输入，确认不会静默写错。
- 调用链回归验证混合批次最终失败，错误包含小数不受支持的原因，本批暂存和正式数据均被清理，其他批次保留；重复新批次仍失败且无残留。无失败时继续成功。
- 回归既有 IBKR 映射、去重、暂存、导入、异步失败及清理测试；不运行依赖个人 XML 的解析测试，不启动带真实数据的数据库或应用。
- `git diff --check` 与相关文档链接检查通过。独立复核涵盖完整差异与验收场景。单元测试不证明真实数据库事务行为，本次不变更原事务边界。
