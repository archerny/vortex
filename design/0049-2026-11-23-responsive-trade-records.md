# 交易记录页与详情的响应式布局

## 背景与目标

交易记录页在笔记本宽度下需要横向拖动才能看到费用和详情入口。窗口进一步收窄时，固定半径的圆环还会被右侧图例挤出绘图区。本轮调整交易列表、详情中的相关交易表和交易统计卡片，以侧栏展开时在 1280 CSS 像素及以上直接查看完整表头和操作列为目标。沿用 [0048 的表格内滚动与筛选栏换行设计](0048-2026-11-22-trade-table-and-event-actions.md)。

## 交易表格

- 主列表与详情中的相关交易表共用列定义和布局。两张表首列保留每条交易的账户 ID，历史空值显示「待补全」。券商名称、账户名称和账户 ID 可在详情的基本信息中查看。相关交易仍以同一本地账户为查询范围。
- 使用 Ant Design 中等行距，收窄横向内边距和证券代码列。长代码单行省略，悬停或打开详情可查看完整值。费用保留原始精度，较长数值可换行。
- 按实际列宽之和确定表格内滚动下限。可用宽度不足时可在表格内横向滑动查看末列。账户、策略和底层证券筛选、排序、分页、金额隐藏与详情跳转沿用现有行为。

## 统计卡片

- 交易类型圆环居中，内外半径随绘图区缩放。图例移到下方自动换行，列出各类型的次数和占比。百分比以图中各类型的次数合计为分母。扇区空间不足时省略内部标签，仍可在图例或悬停提示中读取数值。零交易时保留空态提示。
- 宽窗口三张卡片并排。低于 `lg` 时交易概览单独占一行，低于 `md` 时三张卡片各占一行。使用现有 Ant Design 栅格和 Recharts 组件。

## 实施与验收

1. 在交易列表与详情复用表格布局，统一使用交易详情链接。响应式调整集中在交易统计面板及其样式。接口、账本结构和交易数据沿用现有实现。
2. 以合成交易在 1280、1366 和 1440 像素视口核对表格全列、账户 ID 及待补全状态、相关交易范围、原有行距、长代码提示、精确费用和详情跳转。收窄窗口后检验表格内滚动及末列可达。按普通模块地址检查 `3001` 开发服务返回最新组件和样式。
3. 用合成统计验证宽窄窗口和动态缩放，检查圆环边界、图例换行、小扇区、悬停提示及零交易空态。前端构建和 14 项费用展示与排序测试已在 `ubuntu-dev` 通过，合成图表的浏览器验收覆盖 320、460、820、1150 和 1440 CSS 像素。用户已在页面查看本轮改动。
4. 同步 [前端架构](../knowledge/frontend-architecture.md) 与 [前端开发指南](../docs/frontend-guide.md)。提交前检查文档链接和差异空白。
