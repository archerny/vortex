# IBKR 期权事件精确关联与失败处理

## 背景与目标

用户明确要求精确关联：不得跨券商；找不到期权记录时整次同步失败，交由人工处理；全部条件核对后仍有多个候选，也整次失败。当前查询没有券商约束，单候选无条件接受，多候选先取首个行权价相同项，再按数量或首项兜底；回填异常被吞掉，可能返回成功。

继承 [0012](0012-2026-04-18-ibkr-booktrade-mapping.md) 的 BookTrade 事件分类、股票指向期权侧事件记录及同券商跨批次查找能力，替代其宽松匹配与警告继续策略；沿用 [0019](0019-2026-04-23-broker-import-data-loss-fix.md) 的失败传播和整批清理、[0032](0032-2026-11-17-ibkr-duplicate-content-consistency.md) 的重复内容校验，以及 [0035](0035-2026-11-17-ordered-market-events-and-history-locks.md) 的写锁与历史边界。

这里关联的是同一次行权／指派的期权侧簿记记录，不是更早买入／卖出开仓记录；开仓持仓历史完整性不属于本次回填校验。

## 范围、规则与取舍

- 仍只回填当前批次、未删除、未关联的股票侧行权／指派记录；期权候选允许来自当前或历史批次。只写股票侧的关联 ID，不修改旧期权记录、交易数值或已完成的历史关联。
- 查询在数据库中增加相同 `broker_id` 与币种约束，保留相同交易日、底层证券、事件类型、期权资产类型、期权侧关联 ID 为 0 及未删除条件。代码对实际候选继续核对这些条件，不再因只有一个候选而跳过验证。
- 同时满足方向、行权价、数量。行权的期权侧为 SELL，指派为 BUY；股票方向分别为：行权 CALL→BUY／PUT→SELL，指派 CALL→SELL／PUT→BUY。期权代码须能解析为当前规范的底层证券、有效到期日、C/P 和正行权价，且与资产类型一致。股票单价与行权价用 BigDecimal 精确比较，数量按现有标准乘数 100 用 long 相乘，不舍入、不容差、不发生 int 溢出。
- 到期日是合约身份的一部分，股票侧没有该字段；不以事件日强行推断到期日。两个到期日不同但其他条件均满足的候选属于歧义，失败。拆分、合并多个期权／股票簿记行及非标准合约乘数暂不自动支持，无法一对一验证时人工排查。
- 每条股票记录必须恰好有一个满足全部条件的期权候选；0 或多个均抛出 UNRECOGNIZED。唯一候选若已被另一条有效股票事件记录使用，也拒绝，防止重复占用。已关联股票的重复调用保持不改写。
- 移除回填中的吞异常逻辑；数据库错误与保存错误也向上传播。ImportService 不拦截回填错误，Adapter 返回失败，异步执行器调用既有 FailureHandler 清理本批暂存及正式记录。成功清理后 FAILED；清理失败仍按既有机制 CLEANUP_FAILED，保留原始关联失败原因且阻止继续同步。日志与批次错误只用内部行 ID、匹配数量及人工处理提示，不输出账户、原始成交内容或凭据。

## 实现与兼容影响

1. 扩展 Repository 的候选查询和被占用检查；替换 Worker 的分步猜测为唯一精确匹配。
2. 在现有 Worker、Service 测试中覆盖原问题和错误传播，复用已有批次／真实数据库验证设施检查实际查询、事务回滚、批次清理与重试。
3. 验证完成后更新 knowledge、恢复说明及 TODO 归档，并进行独立复核。

无表结构、迁移、HTTP 接口或前端变更。旧数据不自动修复；以前被宽松接受的新导入现在可能明确失败，需要人工查看报表与本地记录、修正来源或明确业务规则后再重试。空报表、普通成交、期权到期和相同重复记录的现有语义不变。失败只清理失败批次，不删除或重算历史成功批次；所有回填仍通过现有短写事务锁协调。

## 验证与验收

使用 ubuntu-dev 当前工作树、已有工具和缓存；单测纯内存、Mockito 和合成数据，数据库检查只用 e2e 工具自行创建并清理的临时 PostgreSQL 集群，不连接现有账本或真实 IBKR。先运行新增回归复现旧逻辑，再运行受影响单测和后端完整套件；实际执行清单包含嵌套和参数化案例。

验收覆盖同／跨券商、同券商跨批次、CALL／PUT 四种方向、行权价与数量同时核对、币种、不同日期／标的／事件、已删除、格式异常、整数乘法溢出、无匹配、多匹配及交换候选顺序、禁止重复占用、已有关联不重写、异常传播、真实查询过滤及整批失败清理／重试。保留重复同步、历史锁和清理失败回归；不通过弱化旧断言或跳过来通过。更新 `knowledge/broker-sync/brokers/ibkr.md`、生命周期／持久化的受影响说明、`docs/broker-sync/recovery.md`、验证入口与 TODO；其余知识无业务变化时说明原因。

待定项：无。复杂的一对多／多对一及非标准合约支持保留为明确拒绝的后续扩展，不自行猜测。
