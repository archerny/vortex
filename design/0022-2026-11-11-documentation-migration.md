# 历史文档迁移与当前知识初始化

## 背景与目标

基线 `a6623dd` 有 37 份项目自有 Markdown。历史决策、现行实现和操作指南混放在 `docs/`。券商同步尤为明显，同一文件可能同时保留 v1 与 v2 的决策、当时的 DDL 示例和当前故障处置说明。

本次建立可追溯的方案索引和基于代码的当前知识，保留前后端、数据库和券商同步的日常操作入口。

## 范围与依据

- 归档现有 19 份设计记录，并从 Git 补回早期券商同步总体方案和导入一致性 v1。
- 逐文件核对基线的 93 个后端 Java 实现、21 个后端 Java 测试、28 个 Flyway 版本迁移和 47 个前端源码文件（含 2 个测试）。同时核对项目自有 Markdown、构建与数据库配置、部署脚本和开发库脚本。
- 供应商 API 快照保留在 `external-resource/`。本次变更范围为 Markdown。
- 校正会影响实际操作的配置与数据库指南，包括本地配置文件、Flyway 与 JPA 的职责、真实账本的启动风险和已失效的健康检查命令。

## 设计与关键取舍

- `design/` 中的方案独立编号，日期取原始设计日期。索引注明来源提交、原路径、落地状态和替代关系。归档调整 Markdown 内部链接目标，保留历史正文、待办和当时的验证记录。0009 中含真实账户数据的 XML 响应换成合成样例，保留原有元素和字段。原件按索引中的来源提交核对。
- `knowledge/` 按代码、测试源码和迁移描述当前行为。旧方案中的同日事件设想、已替代的续跑状态和旧 SQL 留在历史记录。
- `docs/broker-sync/` 负责接入与排障，保留总入口及 IBKR、Tiger 的接入路径。依然被代码或迁移脚本引用的旧路径用简短导航承接。恢复指南提供对照实现核对的只读查询，人工修改须按批次核对并获得授权。
- 导入一致性的演进见 [v1](0010-2026-04-16-broker-import-consistency-v1.md)、[v2](0018-2026-04-22-broker-import-consistency-v2.md) 和 [P0 修复](0019-2026-04-23-broker-import-data-loss-fix.md)。市场事件和证券名称字段的决策见 [市场事件处理](0002-2026-03-08-market-event-processing.md) 和 [删除证券名称字段](0014-2026-04-21-drop-symbol-name-fields.md)。

## 实现步骤

1. 建立设计和当前知识索引，登记原始文件与目标路径。
2. 按领域编写当前知识与恢复指南，同时按来源快照生成历史归档。
3. 将 README、AGENTS 和券商同步入口指向新目录。为仍在使用的旧路径保留必要导航。
4. 检查变更范围、历史正文差异、相对链接、锚点、命令入口和 Git 空白检查。

## 验证与验收

- 21 份历史记录均能通过索引找到。与各自 Git 来源相比，差异限于 Markdown 内部链接目标和 0009 的合成样例。
- 新建或编辑的项目文档可通过本地链接到达，跨文件锚点可定位到对应标题。
- 表名、字段、接口和命令入口可追溯至源码。部署和联调说明明确数据库目标及隔离要求。
- 本次通过静态核对验证文档。实际连接数据库时另行确认目标及数据授权。
