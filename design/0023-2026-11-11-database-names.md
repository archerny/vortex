# 统一数据库命名

## 背景与目标

后端默认连接使用旧库名，配置说明和重置脚本示例还使用另一套开发库名。统一约定运行库为 `vortex`、隔离开发库为 `vortex_dev`，便于识别项目与环境。

## 范围与设计

- 将基础连接 URL 的默认库名改为 `vortex`。当前工作树通过被 Git 忽略的 `application-dev.properties` 覆盖为 `vortex_dev`。
- 更新资源配置说明、开发库重置脚本和手动基线脚本中的库名示例。数据库用户名独立配置，基础默认用户名仍为 `ledger`，开发角色由实际环境决定。
- 沿用 [文档迁移方案](0022-2026-11-11-documentation-migration.md) 对现行指南和历史记录的区分。手动基线脚本中的历史执行者元数据按原值保留。
- 外部 profile、环境变量或命令行中指定的连接 URL 仍按 Spring 配置优先级生效。已有部署应核对实际库名，并按需显式配置 URL。

## 实现步骤

1. 更新基础配置和三个旧名称示例文件。
2. 为当前工作树创建本地开发配置，登记虚拟机中的连接目标和配置状态。
3. 同步本地配置指南、当前知识入口及本方案索引。

## 验证与验收

- 基础默认 URL 指向 `vortex`，本地 `dev` URL 指向 `vortex_dev`，基础用户名和历史执行者元数据与改动前一致。
- 操作配置与指南中的旧库名示例已清除。确认开发配置和个人环境说明被 Git 忽略。
- 静态核对配置、文档链接、重置脚本语法及差异空白。
- 连接目标或用户尚未准备好时，记录为待配置状态。实际建库和连库验证在核对目标后执行。已有部署可通过显式指定原连接 URL 恢复连接。
