# 券商、托管账户与同步连接统一方案

覆盖 2026-11-21—22 的改动，按用户要求合并本轮未提交的 0047—0051 草稿，以最终决策组织内容；已提交历史方案保留原样。各阶段的实际验证及已撤回实现记录见 [验收归档](../docs/TODO-ARCHIVE.md)，当前能力见 [知识索引](../knowledge/README.md)。

## 背景与目标

用户确认工具用于个人本地记账、券商连接只读，且未使用此前加密方案。沿用 [0045](0045-2026-11-20-ibkr-database-settings-ui.md) 的页面配置流程和 [0046](0046-2026-11-20-ibkr-settings-database-snapshots.md) 的数据库唯一凭证来源，改用明文读写，删除加密、密钥管理及无历史数据的密文兼容；进一步保护留在 [TODO](../docs/TODO.md)。同时纠正“券商即账户”的模型：券商保存客观资料，真实账户负责记账、启停和连接，支持同券商多账户。

## 数据模型与页面

| 对象 | 最终字段与职责 | 页面入口 |
| --- | --- | --- |
| `brokers` | 券商名称、可空且非空值唯一的技术代码、国家／地区、独立简介 `introduction`（500 字符）；没有联系方式、账户备注或启停状态 | 券商管理 |
| `broker_accounts` | 本地主键 `id`、所属券商 `broker_id`、真实账户 ID `account_id`、账户别名 `account_name`、邮箱／电话／备注及 `is_active` | 托管账户 |
| `broker_sync_connections` | 以 `broker_account_id` 为主键／外键，保存券商代码、明文 JSONB 凭证及更新时间；账户删除级联清理连接 | 同步管理 → 同步配置的账户行 |

- 券商与账户一对多，真实 ID 在同券商下唯一；账户名称和真实 ID 最长各 100 字符，真实 ID 不含空白。新账户必须填写真实 ID，所属券商创建后固定。历史“待补全账户”可保留空 ID 修改资料或停用，补齐后不能再清空；有关联账本或批次的账户不可删除。
- 邮箱、电话、账户备注上限为 100／30／200 字符，可选且不作唯一约束。新写入修剪首尾空白；这些字段及券商简介在更新时省略／null 保留，空串清空，超长拒绝。账户备注不反向复制为券商简介。
- 左侧分别保留券商管理和托管账户菜单，托管账户页没有“券商管理”按钮。同步页只配置已有账户，不创建或修改账户资料；需要新增时引导到账户管理。启停仅由账户控制。

## 凭证与同步

- IBKR 配置 Token／Trade Confirmation Query ID；Tiger 配置 Tiger ID／PKCS#8 私钥，资金账号取所选账户的真实 ID。生产运行只读数据库，不回退或自动导入启动 profile，不按券商任取账户。保存配置不请求券商。
- Token／私钥首次必填，后续留空保留、填写替换，确认清空只删除所选账户连接。API 返回非秘密字段及配置／就绪标识，不回传秘密值；日志、错误和测试数据遵守研发约定的凭证输出限制。
- 活动批次期间允许编辑账户及连接，不新增专用编辑锁。IBKR 每份报表捕获同一行 Token／Query ID，SendRequest 与 GetStatement 使用同一 Token，后续报表可读到新配置；Tiger 每批捕获同组凭证及资金账号供全部日期窗口使用。
- 触发前检查账户所属券商、账户启用、真实 ID 完整和连接就绪，批次持久化本地账户与真实 ID 快照；忽略客户端传入的真实 ID。导入归属从持久化批次取得，拉取期间券商代码变化不重新选择账户。IBKR 报表（含空报表）及 Tiger 返回订单须匹配选定真实 ID，否则暂存前整批失败。
- 暂存去重键纳入来源账户，正式交易以本地账户、券商和外部 ID 去重，软删除记录仍受唯一约束。IBKR 原有内容一致性检查及期权关联限定同一账户。沿用全局单活动批次、失败整批清理和清理失败阻塞规则，保留其他账户及成功批次数据，连接配置不随批次清理。

## 账本与接口兼容

- 交易与流水增加 `broker_account_id`，保留 `broker_id`，组合外键保证父券商一致。创建／修改交易、创建流水由所选本地账户推导券商；响应返回更新后的只读账户资料。交易、流水、持仓及批次支持账户筛选，原券商筛选保留。
- 持仓按证券及账户汇总，市场事件逐账户生成交易、回放成本和取整；金额、费用、数量、日期口径不变。历史锁及并发互斥仍覆盖全部账户的关联证券。期权关联不能跨账户，被有效关联引用的来源交易不能单独移入另一账户；软删除引用不阻止移动。
- 连接 API `/api/broker-sync/connections/{brokerAccountId}` 使用本地账户主键。旧只指定券商的写入／同步请求及 IBKR settings API，仅在可唯一确定账户时接受，否则明确拒绝。旧 `GET /api/brokers/active` 兼容返回全部券商；旧客户端须改用账户 API 维护联系方式和状态，不再依赖券商 `isActive`。

## 迁移、部署与失败恢复

迁移按 V31—V35 顺序追加，已应用脚本保持原样，不因文档合并而压缩 SQL。迁移不访问券商，不拆分或重算旧账本。

| 迁移 | 数据处理与失败边界 |
| --- | --- |
| V31 | 将 IBKR Token 列改为明文 `flex_token`；支持无凭证历史库升级，不提供历史密文转换 |
| V32 | 建连接表，先按券商主键迁入旧明文 IBKR 配置并删除单例表；存在 Token 却没有匹配 IBKR 券商行时整次回滚，修正关联后重试 |
| V33 | 每个旧券商创建真实 ID 为空的“待补全账户”，迁入连接及全部历史交易／流水（含软删除、事件行），保留原数值、关联和更新时间。连接改为账户主键；历史批次仅按正式交易能证明的唯一原券商补归属，未知批次及真实 ID 快照不猜测；历史暂存空账户保留，新写入／更新须有来源账户 |
| V34 | 将券商邮箱／电话／旧账户描述迁至唯一待补全账户，否则迁至唯一账户，无法唯一确定时新建“待补全账户（原券商资料）”；三项旧资料均为 null 时不新增账户。保留旧字符串、已有账户审计及账本／连接／批次，删除券商旧列 |
| V35 | 新增独立券商简介，删除券商状态；保留账户备注及现有账户状态，不把旧券商状态再次复制到账户。V33 当时初始化账户状态的历史规则不变 |

部署先停止旧后端、核对目标库并备份数据库（包含明文凭证），由新后端执行未应用迁移及 JPA 校验，再提供匹配前端。升级后先检查待补全账户和历史归属，补齐真实 ID 才能同步。迁移失败事务回滚，修正后重试；回退旧应用须恢复升级前数据库并处理备份后的新增写入，不能仅回退应用包。操作细节见 [账户指南](../docs/accounts.md#迁移与恢复)。
