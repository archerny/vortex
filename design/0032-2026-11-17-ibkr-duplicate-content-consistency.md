# IBKR 重复记录内容一致性校验

## 背景与目标

当前暂存按 `orderID`／`tradeID` 是否存在直接跳过，正式入库也按外部订单 ID 直接跳过，不能发现同 ID 的不同数量、金额、费用或来源信息。用户明确采用“ID 相同、内容一致则跳过；ID 相同、内容不同则报错，不自动覆盖或重算”的规则。

沿用 [0031](0031-2026-11-17-trust-ibkr-reported-completion.md) 的使用前提：只同步历史交易，默认报表记录已执行完成，不查询订单终态、不因 `P` 或多笔成交拒绝。本方案落实 0031 留待确定的重复内容处理，不开发部分成交生命周期。

## 范围与历史决策

沿用 [0013](0013-2026-04-21-ibkr-staging-schema.md) 的订单汇总入账与成交明细暂存，沿用 [0018](0018-2026-04-22-broker-import-consistency-v2.md)／[0019](0019-2026-04-23-broker-import-data-loss-fix.md) 的独立事务、整批失败清理和原批次保留。保持现有 ID 唯一键及表结构，不新增迁移、依赖或 API。

## 设计与关键取舍

- 暂存通过现有 `findByOrderId`／`findByTradeId` 取得原记录，先把输入映射为候选暂存实体。新 ID 正常保存；相同 ID 比较业务内容，一致则跳过，不修改原行及其批次归属；不同则立即抛出 UNRECOGNIZED 分类异常，阻止进入本批导入阶段。
- 比较暂存表实际保存的全部来源业务字段，包含账户、证券、方向、币种、日期时间、数量、价格、金额、费用、订单／成交／执行标识及成交 Code 等。不比较数据库主键、批次、处理状态、错误说明、导入关联和审计时间。Order 未保存的 `exchange`／`code` 不增加新持久化字段；TradeConfirm 已保存字段照常比较。
- 数值字段使用完整精度 `BigDecimal.compareTo`，忽略尾零和科学计数法表示差异，保留正负号意义，不舍入。其他文本去除首尾空白，空白与 null 等价；缺失数值不等同零，日期和标识不作数值转换。Code 按分号切分、去空并按集合比较，不因排列次序产生冲突。
- 必需 ID 缺失或为空时报错，不能把无 ID 输入当作可幂等记录。相同 `tradeID` 的父 `orderID` 不同也算冲突。新 `tradeID` 按新记录处理，不额外建立成交集合完整性或订单终态证明。
- 正式入库的重复订单检查也不能只查存在：在该分支映射当前候选，查询已有正式交易，比较已有表可表达的业务字段（券商、日期、资产、证券／底层证券、方向、数量、单价、金额、费用、币种、触发类型及引用类型）。不比较批次、软删除状态、时间戳或后续回填的 `triggerRefId`，不恢复软删除或覆盖用户已有记录。该兜底只验证正式表的业务投影，不声称恢复了缺失的原始暂存信息。
- 冲突诊断通过记录类型、已有内部行 ID 及差异字段名定位，不输出账户、原始记录或字段前后值。复用既有分类与错误传播，正式导入冲突由既有失败标记和批次检查处理，消息在清理后仍可查看。

## 验证与验收

- 分别从真实 StagingWorker 入口复现同订单数量变化、同成交费用变化在旧算法上被跳过的问题，修复后得到可定位且不泄露字段值的冲突提示。
- 覆盖暂存来源字段差异、跨账户、成交父订单变化、数值尾零／极小费用／符号、空值、Code 顺序、管理字段变化不误报、缺失 ID、同批重复、跨窗口重复及不同 ID 正常保存。
- 正式入库兜底覆盖相同业务投影跳过、费用／数量／券商等差异失败，原正式交易不被保存、修改或重算；用户软删除与派生关联不被重置。
- 使用真实解析／暂存／适配器／异步执行／失败处理／清理组件和 Mockito 仓储、模拟网络构建内存调用链。冲突后不得 COMPLETED，本批新数据被清理，之前成功批次的数据完整保留，重复提交同一冲突仍失败；清理失败时沿用 CLEANUP_FAILED。
- 按 `docs/unit-test-spec.md` 使用纯内存 JUnit 5／Mockito，运行相关券商与清理回归，记录环境、命令、退出状态及结果。单测不代替真实数据库事务或并发唯一约束验证；本次无数据库结构修改，不执行历史数据对账。

## 调用方、历史数据与失败处理

重复且内容不同的输入将从“成功跳过”变为明确的批次失败；重复且一致的输入维持幂等。只清理失败批次自己新增的数据，不删除原成功批次，不覆盖旧行，也不自动更正或重算历史账本。冲突需要人工核对来源后再处理，重试本身不会消除冲突；清理失败继续使用原有阻塞及恢复方式。没有新增部署迁移或历史回填。
