# 前端直接展示完整费用精度

## 背景与目标

用户在 2026-11-17 修订 [0029](0029-2026-11-17-preserve-trade-fee-precision.md) 的展示决定：列表、详情和统计与后端一致，直接保留原始费用小数，不再固定显示两位。数据库与后端不舍入、编辑无损、历史数据不修复的要求继续有效。

## 范围与设计

- 移除交易列表、关联交易表、详情及费用统计中的两位格式化，直接显示后端精确十进制文本。新增和编辑继续使用字符串费用值，遮罩、空值和零费用提示保持现有语义。
- 沿用 0029 的 `feeExact`，新增统计费用的只读精确字符串字段，保留原 JSON 数字字段兼容现有调用方。前端优先使用精确字符串，避免 JSON 数字进入 JavaScript 后丢失有效位。统计仍完全在后端按币种汇总。
- 费用列排序按十进制数值精确比较，不将展示值转为浮点数。已有两位费用和旧响应继续兼容，不引入依赖。
- 仅调整交易费用；成交价、成交金额、百分比和其他页面的展示口径保持现有规则。V29、费用计算规则及既有历史方案正文保持原样。

## 实现步骤

1. 新增本方案与索引，说明替代 0029 的前端两位展示决策。
2. 补齐统计 DTO 的精确文本，前端列表／详情／统计统一使用原始费用文本，更新相关回归。
3. 在当前工作树对应的 Ubuntu 环境运行后端相关单测、前端单测和构建；在仅含合成接口的页面核对三处展示。
4. 更新当前知识与费用事项归档，保留此前决定及已执行验收的历史；独立复核最终完整差异。

## 验证与验收

- 高精度和极小费用在列表、详情、统计中展示完整数值，不固定小数位、不补齐到两位，也不因 JavaScript 浮点转换丢失位数。新增／编辑提交继续与显示原值一致。
- 统计 JSON 仍保留原数字字段，新增精确字段与对应 `BigDecimal` 完全一致，包含科学计数法可表示的极小值和零／缺省值。
- 前端用合成数据验证显示、零值判断、不同量级和接近数值的精确排序，以及旧响应兼容；浏览器确认三处展示，不连接现有账本或券商。
- 本次不修改 V29 或 ORM 费用映射，沿用 0029 已通过的隔离数据库迁移验证，不重复操作数据库。运行 `git diff --check` 和文档链接检查。

## 影响与失败处理

接口只增加只读响应字段，原数字字段及请求语义不变；不迁移或重算历史数据。加载失败仍沿用现有页面错误处理；费用为空显示缺省提示，不替换成两位展示值。代码尚未部署，现有数据库不在本次操作范围。
