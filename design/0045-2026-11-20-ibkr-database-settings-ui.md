# IBKR 账户关联与数据库凭证配置页面

## 背景与目标

用户实测同步下拉框没有IBKR，也没有Flex凭证管理入口。现有发现接口只返回已用broker_code关联适配器的记账券商，BrokerService更新却未保存页面提交的brokerCode；Token／Query ID仅由启动配置提供。此前后端链路可运行，不代表页面已具备完整使用流程。

用户明确选择将凭证保存在数据库。沿用 [0011](0011-2026-04-17-broker-registration.md) 的broker_code发现方式和单IBKR适配器模型、[0009](0009-2026-04-14-ibkr-flex-web-service.md) 的Token／Trade Confirmation Query ID，以及 [0036](0036-2026-11-17-market-event-write-coordination.md) 的短写协调；不改交易匹配和账本口径。

## 范围与页面行为

- 同步管理增加“同步配置”页签，提供IBKR记账账户选择、Flex Token和Query ID。已有绑定时直接展示；未绑定时可选已有未绑定账户，或通过既有创建券商API新建一个IBKR记账账户。保存配置与绑定已有账户在同一后端事务完成，不根据名称猜测或批量修改历史账户。
- 修复账户管理中brokerCode更新不保存；统一验证非空代码唯一，避免把两个账户关联到同一适配器。配置保存不自动转移其他已绑定账户，冲突时明确说明。账户基础字段和既有交易不改写。
- Token只写不读，页面只显示已配置状态，重新打开不回填Token；留空保留当前Token，首次无Token则要求输入。Query ID可见可编辑。提供明确确认的清空凭证操作；清空后重启不会恢复旧启动凭证。保存成功代表本地配置完整，不暗示已经过真实IBKR授权验证，不自动请求券商。
- 新建同步弹窗在缺IBKR账户／配置时给出到配置页的入口，空券商列表不再持续显示加载中；保存后刷新券商选项。同步状态仍由用户刷新批次查看。

## 数据、接口与关键取舍

- 新增V30表ibkr_sync_settings，保存单例标识ibkr、Token密文、Query ID和更新时间；不把凭证放进brokers响应。无旧交易迁移或历史数据兼容逻辑，原配置文件仍可在数据库尚无配置时提供启动值；一旦有数据库配置（含显式清空），以数据库为准。
- GET／PUT／DELETE `/api/broker-sync/ibkr/settings`：GET只返回记账账户、Query ID、Token是否存在和就绪状态；PUT接收账户ID、Query ID及可选新Token，事务内绑定账户并保存；DELETE持久化清空状态。响应不含Token明文／密文，异常和对象toString也不输出Token。
- Token使用JDK已有AES-256-GCM加密，每次使用随机nonce。随机主密钥保存在工作区内被Git忽略的`.local/`，目录／文件限制为700／600；可用后端属性指定位置。数据库保存密文，主密钥不入库或Git，备份／迁移须同时保管密钥，密钥不可读或密文损坏时明确失败，不生成新密钥伪装恢复。新增密钥只在保存首个Token时创建。
- 保存／清空与同步批次创建共用LedgerWriteLock；存在PENDING／PROCESSING／CLEANUP_FAILED时返回409，避免批次中途换凭证或账户。BrokerService对同步标识变更使用相同协调。数据库提交后才原子更新运行时Token／Query ID；失败不使内存提前生效。客户端读取同一份凭证快照，后续同步使用新值，无须重启。
- 不新增依赖，不新增登录／多账户系统或自定义Flex域名输入。沿用本地应用的访问边界；凭证读写是明确页面操作，后台真实同步仍须用户手动触发。

## 实施与验证

1. 先补迁移、配置实体／仓储、加密组件、配置服务／DTO与控制器，修正BrokerService标识更新及错误响应；再接通页面与API封装。
2. 单测在内存中运行，仓储／网络模拟；覆盖加密往返和篡改、Token不回显、首次／留空／替换／清空、事务失败不提前更新内存、唯一绑定、活动批次拒绝及原重复同步行为。前端覆盖API契约、Token留空保留与清空，以及页面静态展示；不新增安装。
3. 使用e2e自建临时PostgreSQL验证空库到V30、V29历史库升级、合成旧数据不变、真实密文落库、服务重建读取、事务失败回滚与活动批次协调。浏览器用合成账户／凭证核对空状态→配置→IBKR可选、保存／刷新／清空及错误展示，绝不请求真实IBKR或写真实账本。
4. 运行相关与最终全量后端、前端单测和构建，核对实际执行清单，独立复核涉及数据库／安全的完整差异。测试产物和加密密钥仅在工作树或允许/tmp，既有本地凭证和根目录备份不提交。

## 部署、失败与文档

先应用新增迁移，再启用新接口；旧配置无数据库覆盖时保持原使用方式。回退应用可保留新表，部署迁移不删除已有表或数据；备份配置数据库时保管对应主密钥，无法解密则恢复正确密钥或另行明确处理，不自动覆盖。
