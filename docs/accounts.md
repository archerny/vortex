# 券商与托管账户

## 三种标识

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `brokers.id`／`brokerId` | 券商主数据的本地主键 | 券商名称、代码、国家／地区和简介；一个券商可有多个账户 |
| `broker_accounts.id`／`brokerAccountId` | 托管账户的本地主键 | 交易、流水、持仓筛选、同步连接和批次归属 |
| `broker_accounts.account_id`／`accountId` | 券商提供的真实账户 ID | 页面识别账户、同步结果归属校验；Tiger 使用资金账号 |

账户名称 `accountName` 是用户填写的别名，券商名称 `brokerName` 仍表示券商。同券商真实账户 ID 唯一；不同券商可以使用相同 ID。本地账户主键不应填写到真实账户 ID 输入框。

## 页面操作

1. 在**券商管理**维护券商名称、券商代码、国家／地区和简介，不设置券商启停。操作列中的「详情」展示完整简介和券商资料，「更新」进入编辑。简介字段为 `introduction`，最多 500 字符，与账户备注 `description` 分开保存。代码可空，非空值唯一；可选 `futu`（富途）、`tiger`（老虎）、`ibkr`（盈透）、`schwab`（嘉信）、`firstrade`（第一证券）、`csc`（中信建投）。目前只有 `ibkr` 和 `tiger` 对应已实现适配器，其他代码仅标识券商，仍可手工记账。见 [0053 券商代码](../design/0053-2026-11-26-broker-management.md#券商代码与同步能力)。
2. 在**托管账户**（`#/broker-accounts`）选择已有券商，填写账户名称及真实账户 ID，可填写该账户关联邮箱、手机号／电话和账户备注，并设置启停。同券商可重复新增不同真实账户 ID 的账户。所属券商创建后固定。
3. 在**同步管理 → 同步配置**找到具体账户，填写该账户连接凭证。IBKR 为 Token／Query ID，Tiger 为 Tiger ID／私钥；Tiger 资金账号来自账户资料。秘密字段首次必填，后续留空保留，填写新值替换；清空连接须确认，仅影响该账户。当前凭证明文保存于数据库，不回传秘密值。
4. 在**同步批次**选择具体账户及日期范围。只有账户启用、真实 ID 已补齐且凭证完整时才可选。配置保存不请求券商；批次结果以刷新后的状态为准。仍保持全局最多一个活动批次，跨账户也不能并发触发。

交易新增／编辑、流水新增及各列表筛选使用本地账户主键。列表显示券商名称、账户名称和真实 ID；持仓按证券及账户独立汇总，市场事件按账户生成交易和计算成本。历史锁仍覆盖全部账户的关联证券。期权关联及券商重复记录检查限定同一账户；被有效期权关联引用的来源交易不能单独移到另一个账户。

有关联交易、流水或同步批次的账户不能删除，可停用。迁移的待补全账户可在不知道真实 ID 时先改名或停用，保留空 ID；补齐后不能再清空 ID。修改真实 ID 不会迁移账本、拆分历史或重写批次快照；操作前确认该记录仍代表同一个实际账户。活动批次期间允许编辑资料与凭证，进一步保护留在 [TODO](TODO.md)。

## API 约定

- 券商的 `introduction` 可选，更新省略／null 保留、空串清空；响应不再含 `isActive`。旧 `GET /api/brokers/active` 兼容返回全部券商，启停只通过账户 API 维护。券商通过左侧菜单进入，托管账户页不提供“券商管理”跳转按钮。
- `/api/broker-accounts` 支持 GET（可选 `brokerId`）、POST；`/{id}` 支持 GET、PUT、DELETE。新账户必须填写真实 ID；所属券商不能通过 PUT 改变。可选字段 `email`、`phone`、`description` 上限分别为 100／30／200 字符；更新时省略或传 null 保留，传空字符串清空。不同账户可以共用邮箱／电话。券商 API 不再返回或保存这些账户资料，旧调用方须改用账户 API。
- 交易与流水写入优先传 `brokerAccountId`，服务端填充券商；若同时传 `brokerId`，必须与账户所属券商一致。旧请求只传 `brokerId` 时，恰好一个账户才接受，否则返回 400。响应中的账户资料为只读。
- 连接路径 `/api/broker-sync/connections/{brokerAccountId}` 使用本地账户主键。V32 曾用券商主键，V33 后不能继续假定二者相同。
- 同步触发提交 `brokerCode`、`brokerAccountId` 和日期；真实 `accountId` 由服务端读取并保存快照。旧省略账户的请求仅在唯一账户时有效。旧 IBKR settings API 保留券商主键语义，多账户时拒绝，使用连接 API。
- 交易、流水、持仓和批次查询支持 `brokerAccountId`。历史批次真实 ID 快照为空时，页面可展示当前账户资料；本地归属未知时明确显示“历史归属未知”。

## 迁移与恢复

[V33](../backend/src/main/resources/db/migration/V33__separate_brokers_and_accounts.sql) 新建 `broker_accounts`，每个已有券商创建一个“待补全账户”，真实 ID 保持空值。所有历史交易和流水（含软删除和事件生成记录）关联到该账户，保留原券商、金额、数量、日期、费用、关联 ID 及更新时间，不自动拆分或重算。

原连接迁给该账户。历史批次仅在其已有正式交易能确认唯一原券商时补本地账户；不按当前券商代码猜测，空批次或多归属批次继续未知。历史暂存空账户行保留，新写入／更新的暂存行须有来源账户。新唯一索引按账户区分外部订单／成交 ID，交易与流水增加账户及券商一致性的组合外键。迁移不访问券商，也不根据旧 Tiger JSON 猜测真实资金账号。

V34 将邮箱、电话及原“券商账户描述”迁入 `broker_accounts`，从 `brokers` 删除对应列。旧资料优先迁到该券商唯一的待补全账户，否则仅有一个账户时迁给它；无法唯一确定时新建“待补全账户（原券商资料）”保存。没有旧资料的券商不新增账户。迁移保留旧字符串原值和已有账户审计时间，不改变原交易／流水／连接／批次归属。新增的资料待补全账户没有账本，用户可确认归属后将资料填写到正确账户，再删除该待补全账户。

V35 新增独立券商简介并移除券商状态。从 V34 升级保留每个账户的当前状态，旧券商停用不再阻止已启用账户，也不将账户备注反向填为简介；V33 当时初始化账户状态的历史规则保持原样。

部署时先停止旧后端，核对目标数据库并备份数据库（包含明文凭证），然后由新后端执行未应用迁移至 V35 及 Hibernate 校验，再发布匹配前端。升级完成后先检查待补全账户及历史归属，补齐真实 ID 后才发起同步。旧版本写入缺少账户字段，不应与新结构混用。

迁移错误在同一事务回滚；保留备份与错误信息，修正原因后重试，不编辑已应用迁移。需要回退旧应用时，同时恢复升级前数据库，并处理备份后新增写入，不能仅回退应用包。

方案见 [0047](../design/0047-2026-11-21-broker-accounts-and-sync-connections.md)，当前数据契约见 [同步持久化](../knowledge/broker-sync/persistence.md)。临时 PostgreSQL 的空库初始化、历史升级和失败回滚、分账户 JPA／HTTP／导入验收见 [e2e](../e2e/README.md#ibkr-settings-check) 与 [验证归档](TODO-ARCHIVE.md)。未使用真实账本或真实券商验证。
